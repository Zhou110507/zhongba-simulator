# 战术进攻被三杆门槛阻塞（v12）

用户截图显示“直打进攻：模拟验证合法进球，1.10 m/s、高杆 0.50 R”，却因前瞻不足禁用出杆。原因是单杆战术中的 `attack`、`kick_attack` 没有加入战术门槛豁免；这些方案没有多杆 `routes`，因此永远无法凑齐进攻队列。另外，队尾自然搜索结束且找不到续接时，原逻辑只记录失败终点，永久保留不可执行的两杆队列。

## 修改后的行为

- 连续进攻仍需当前杆及后续两杆已验证。补算期间保持队列，不提前出杆，不重搜已验证前序；时间／次数切片结束继续使用同一搜索及缓存。
- 确认找不到稳健续接，或队尾任务异常有日志时，从当前真实球位计算独立战术。优先合法进球，再考虑直打防守、无法直达时的解球；没有验证到合法方案时仍可有界尝试并明确犯规风险。
- 单杆直打进攻、解球进攻、防守、解球与风险尝试不冒充三杆连续进攻。带有多杆路线的方案即使加了战术标签，也不能绕过验证。
- 原未接通路线留在服务内部供诊断，界面显示正在转入当前局面的战术；完成后自动执行。取消、球位、对局版本或模型变化阻止旧结果发布。
- 对局仍由原物理仿真及规则提交；没有移动球位、放松几何校验或改动训练权重。

## 验证

`tests/fixtures/ai-tactical-gate-deadlock.json` 保留用户报告后磁盘中的原对局，出杆由未修改的战术选择器重新生成。不是从截图推测的球位，也不冒称保存了旧进程内的原 AI 任务。

运行 `python -m tools.audit_tactical_continuity` 在内存副本上重放，不改原对局文件：旧门槛拒绝，新门槛允许；实际打进 5 号球，无犯规，版本从 3 推进到 4，重复提交被拒绝。详细结果见 [回放记录](../validation/tactical_continuity_v12.json)。耗时仅为这次出杆执行，不是规划耗时或清台率。

相关 Python 回归 133 项通过，覆盖真实故障局面、三杆门槛、预算续算、当前球位战术转换、队尾异常、取消与球位／模型失效、四档执行、原仿真结果有效性及 HTTP 启动。全部前端测试 57 项通过，包含自动战术执行、慢补算等待后继续、旧响应失效，以及原练习台、反算台、回放、球号显示和模式切换。Windows 沙箱限制 pytest 临时目录访问的运行未算作通过；使用正常权限重新运行上述检查后通过。

本地 `http://127.0.0.1:8767/` 健康接口与网页版本均为 `tactical-continuity-v12`。另建三球练习局勾选自动对打：先合法打进 3 号球；随后两杆队列未接通，页面显示正在选择当前局面战术，随后自主执行防守并正常换手给玩家，全程没有手动点“执行”。该演示证明可继续完成当前杆，不宣称此次清台。原用户对局文件保持不变。
