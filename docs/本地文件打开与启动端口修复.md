# 本地文件打开与启动端口修复

版本 `local-launch-guard-v11`，基于 `74f81c5d7b3e14342eec7a91652ef83165f93c96`。

本次截图实际打开的是 `C:/Users/lenovo/Documents/ChatGPT/poll/web/index.html`。文件地址不会启动本地物理服务，页面使用的 `/assets/` 资源和 `/api/` 也不能从文件协议下正常访问，因此出现无样式、控件未初始化、一直显示连接中的页面。

`web/index.html` 增加独立于外部资源的本地文件启动提示。直接打开文件时，明确要求返回项目根目录并双击 `启动练习台.cmd`；通过正常 HTTP 服务打开时，该提示不改动页面或初始化逻辑。

检查中还发现默认 8766 端口存在旧 `pot-first-natural-v1` 服务。Windows 下原 HTTPServer 的地址复用允许新旧进程同时监听同一地址，导致新进程报告启动成功、浏览器却仍访问旧 API。本地服务器现使用 Windows 独占地址；启动器先寻找附近同版本服务，再避开已知占用端口启动，不终止旧进程，不覆盖对局记录。非浏览器模式保留显式端口的原有语义，非端口占用的权限错误不吞掉。

实际启动命令从 8766 自动选择了 8767，健康检查及页面页脚均确认 `local-launch-guard-v11`，样式、球桌、力度／杆法控件恢复。当前入口为 `http://127.0.0.1:8767/`；以后双击启动器会自动发现并打开对应地址，不要求用户记住固定端口。

37 项相关 Python 测试和 51 项前端测试通过，包括真实同地址重复监听被拒绝、旧版避让、同版复用、启动范围有界、权限错误不被掩盖、正常页面与 API、文件打开提示及原有 UI 行为。文件协议分支使用隔离 JavaScript 测试验证，正常入口在实际浏览器确认；没有重新训练或改动物理／AI 规划参数。
