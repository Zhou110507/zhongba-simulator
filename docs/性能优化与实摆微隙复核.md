# 性能优化与实摆微隙复核

2026-10-20，修复规则对局计算及拖动瞄准卡顿。第四阶段反算未开始。

## 定位和修改

旧实现有三处明显浪费：指针每次移动都会重绘背景、重新创建规则卡片，并可能发起整杆请求；回放每帧从头扫描全部运动段，重采样所有历史轨迹；接口在每个接触事件中重复输出碰前碰后的整桌状态。偏角紧密球堆样例有 1541 段运动、2388 个事件，响应约 30.2 MB。

现在拖动指针合并到每个动画帧，第一碰位置在本地即时计算，完整路线只在点击预览或出杆后计算。球桌背景、球的绘制和完成的轨迹都缓存；解析抛物线用等价二次贝塞尔曲线绘制；回放球位采用二分定位，反向拖动时间轴会清空并重建轨迹缓存。规则面板仅随对局状态变化重建，按钮限制仍每次刷新；进袋标记按变化更新，事件高亮只更新跨过的行，文字更新节流。停止播放后不继续空转动画循环。

浏览器使用 `playback-v1` 精简事件格式，保留真实第一碰快照和全部运动段，支持 gzip。完整审计导出仍保留原有事件碰前/碰后状态。规则判罚仍在服务端使用同一模拟结果。后台缓存静态几何、减少距离检测的向量对象创建，并对一、二次方程使用稳定解析求根；没有提高力度、修改摩擦或降低持续接触求解精度。

## 本机测量

同样的初态：CBSA 2540×1270 mm、理想紧密球堆、种子 0、瞄准 0.45°、杆头速度 5 m/s。旧版本为 `9efa670`。这里比较同一个紧密球堆，和新增微隙功能分开评估。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 模拟及结果整理（不含 JSON 编码） | 7.628 s | 4.078 s |
| 其中物理求解 | 5.042 s | 3.825 s |
| JSON 编码 | 0.729 s | 0.286 s |
| 未压缩 JSON | 30,189,660 B | 10,647,841 B |
| 浏览器实际传输格式 | 30,189,660 B | 2,331,695 B（gzip） |

同一运动记录按 60 Hz 回放，旧算法需访问 43,629,401 个轨迹采样顶点；缓存算法绘制 28,212 段解析曲线。它是工作量对照，不等于帧率提升倍数。浏览器实拖的一次 JavaScript 绘制样本约 0.3 ms，回放初段一次样本约 0.8 ms；完整预览或跳转末尾首次重建轨迹约 10–14 ms。这些是本机样例，不保证所有机器或局面都达到相同耗时。

微隙样例另测为：相同种子、角度和力度，0.2 mm 微隙，模拟及整理约 0.577 s，压缩传输 370,332 B。它的初态和紧密球堆不同，不能把这个差异全部归为代码优化。

## 随机摆球与规则

[CBSA 2017 公开规则](https://cbsa.cssf.net.cn/annoucement/2017/0120/142126.html)第三部分第 3 条要求目标球彼此紧贴。因此，“规范紧密摆球”保留；按用户要求，新对局默认采用不超过 0.2 mm 的随机微隙，也可选 0.5 mm。两档都明确标为工程设置，并非实测摆球误差分布。

微隙由球堆整体小幅扩张与逐球有界扰动组成，保证不重叠、最前球中心仍在置球点，8 号在第三排中间、底角一全色一花色。最大微隙指原紧密球堆的相邻球之间的净间距，不是整个球堆偏移量。普通新局使用新的随机种子；存档保留种子及真实球位，刷新不会重摇。相同种子、幅度和杆法可复现结果；要求重新开球时更换布局种子。

这模拟的是非理想实摆，同时继续采用已选择的中八判罚版本；它不声称严格满足“所有球紧贴”的器材准备条件。已有紧密球堆存档继续保持原球位，点击新对局才采用新设置。

## 球的大小

重新核对上述协会原文第 2 条：球径 57.15 mm，台面内沿 2540×1270 mm。球径/长边 = 2.25%，短边约容纳 22.22 个球径；原乔氏公开自由台型 2540×1260 mm 则约容纳 22.05 个球径。绘制球半径与台面长度使用同一个等比缩放系数，Canvas 的 1600×900 与 CSS 的 16:9 相符，缓存球图像仍按实际半径绘制。本次没有放大或缩小球。

## 自验与复验

428 项 Python 和 11 项 JavaScript 测试通过。新增微隙不重叠/范围/复现、默认随机种子、精简响应与完整响应的球位和判罚一致性、gzip、解析回放曲线和倒放缓存测试。84 组瞄准对照、108 组文献公式控制、6 组旋转实验与原练习预设通过。浏览器验证拖动不提交整杆请求、预览、正式出杆、规则保护、向前/向后跳转；未发现控制台错误。
