# AI 需求与验收基线

开始新的 AI 修改前重读本文件和项目 AGENTS；阶段验收未通过时先修反馈，不能把一次补丁当作整项目目标。后续用户澄清优先；改动前后必须说明是否与这里的目标冲突。

## 目标与决策优先级

1. 目标是普通人能复刻的清台思路，保留软件原来的练习、反算、规则、尺寸与动力学功能。不是利用模拟精度每次清台。
2. 进球优先，同时兼顾下一球的进球宽容度、白球距离与角度、舒服的手架和再下一杆的连接。允许适当杆法和多库，不能因走位复杂就选难进的当前球，也不能为简单走位留下难球。
3. 后斯诺、库边出杆、高低杆空间、连击风险等真实限制仍需验证。不借其他球精确停白球；必要 K 球须打开本组球且验证误差后续接。优先空心进袋；借袋角只有收益值得风险时采用，白球借袋角控位须有额外代价。
4. 持续至少三杆前瞻，残局保持原清台深度。打 1 时从已知 3 的终点补 4，保留已经算好的 2、3，不为了提速缩短深度或重算已知前序。球位或规则失配才作必要失效处理。
5. “三杆”是规划目标，不能成为拒绝进球的绝对条件（用户 2026-10-22 澄清）。补算预算用完继续同一搜索；固定末端接不上，先尝试调整未执行末杆。仍未接通应保留已验证进球继续打，如实显示不足，不能随意丢弃进攻改打防守。计算异常不等于当前进球失效；仍须检查真实场景和动作约束。
6. 没有可用进球才考虑防守；能直接打到合法球而打不进是直打防守，无法直接触及才需要解球，露球边也算能打到。防守不能仅凭合法触球或球心被挡下结论，要检查对手实际进袋线路以及落点误差。没有好解法仍完成有界尝试并明确风险，不能停着不打。
7. 冲球从离线训练的少量固定位置／方案中选择；随机正微隙球堆，冲后才读取球位。不能每次冲前搜索下球。普通击球与开球力度区分杆头和白球速度，并保留实测量级依据。
8. 四档共用最高档规划，仅在实际方向／力度施加不同正态误差。AI 是中八对局可选对手；玩家球号用真实球样式，未分组隐藏、分组排序、进球移除；玩家的力度与杆法可直接操作。

## 防止局部修复破坏整体

- 用户截图和真实故障数据作回归；不能仅靠这一局面证明改好了，更不能用它反复调权重。模型参数和人类约束变更必须有独立训练／验证分组与来源；工程评分不是职业或真人概率。
- 新策略以预先锁定的未参与调参局面比较修改前基线，记录进球、犯规、对手进袋机会、真实验证深度、复用与计算量。分清单杆测试、连杆规划和整局测试，不能互相替代。
- 验收不回流训练，模型哈希核对；发现失败应保留并披露，不挑好看的结果。不能因不理想就不停换验证集；后续训练另取数据，最终测试另留独立集合。
- 检查原功能回归，再更新独立后台服务，核对实际页面和健康版本；相关检查通过后同步私有 GitHub 并注明提交，等待用户验收反馈。
